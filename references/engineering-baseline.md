# 工程基线标准

## 1. 目的

在第一个业务垂直切片之前，先让真实开发仓具备“可安装、可启动、可测试、可迁移、可恢复、可交接”的基座。工程基线是特殊工程任务，不需要母骨架替技术细节决策，但不得借它改变产品范围。

## 2. 开工原则

- 先读取真实代码仓、锁文件、现有测试和 CI，不根据想象生成技术栈。
- 已有可工作的配置不得为了套模板而替换；先评估差异和迁移成本。
- 不自动提交、推送、合并或部署；未经实测不得写基线通过。

## 3. 必查清单

| 基线项 | 必须形成的内容与证据 |
|---|---|
| 资产登记 | 开发仓、模拟器、部署、交付物、旧代码及证据目录登记到 `docs/ASSETS.md` |
| 依赖与环境 | 语言/运行时版本、包管理器、锁文件、可复现安装命令 |
| 配置与密钥 | 环境变量样例、密钥来源和访问边界；不得硬编码真实密钥或把秘密提交入库 |
| 启动与停止 | 本地启动、停止、健康检查命令及实测结果 |
| 数据库 | 初始化、迁移、回滚和测试数据重置方式；不适用需写理由 |
| 错误与日志 | 统一错误响应、异常边界、结构化日志、必要审计字段 |
| 代码质量 | 与真实技术栈匹配的 lint、format/typecheck 及实际运行方式 |
| 测试体系 | 单元、集成和必要端到端入口；固定模拟数据/随机种子；真实测试输出 |
| CI | 根据现有或新建开发仓确定 CI 命令、触发条件和证据保留；不预置通用假模板 |
| 模拟与真实适配 | 模拟设备/外部服务与真实适配器共享契约，避免模拟路径与生产路径分叉 |
| 恢复与回滚 | 备份恢复、配置/数据库回滚或明确 N/A 理由；生产目标需实测 |
| 可观测性 | 健康检查、结构化日志；试点/正式目标另评指标、告警和必要链路追踪 |
| 文档与交接 | 更新 STATUS、TESTING、OPERATIONS、ASSETS、DECISIONS 和开发交接手册 |

## 4. 成熟度目标

- `DEMO`：最小可复现启动、正常路径测试和集成证据。
- `PILOT`：另需异常、权限、审计、部署和回滚证据。
- `PRODUCTION`：另需安全、性能/容量、备份恢复、健康/指标/告警、迁移与发布验证。

成熟度是目标证据等级，不等于对外承诺。具体业务仍需另行验收。

## 5. 完成判据

- 必查项均有实测证据或合理 N/A；
- 新窗口按手册能完成安装、启动和测试；
- 另一个 Agent 能复现相同结果；
- 基线未通过时，业务切片只能处于 BLOCKED，不得以“先写完再补基线”跳过。
