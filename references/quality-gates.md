# 质量闸口与证据标准

## 1. 三个成熟度层级（不得混用）

| 层级 | 用途 | 最低证据 |
|---|---|---|
| 演示级 | 验证业务流程 | 正常路径可运行，模拟数据明确标识，不宣称投运 |
| 试点级 | 小范围真实使用 | 异常、权限、测试、审计、部署与回滚验证 |
| 正式交付级 | 生产长期使用 | 安全、性能、备份恢复、监控、迁移、运维及发布验证 |

工程质量与业务确认是两条线：模拟数据不降低工程要求，工程测试通过也不等于现场业务已确认。

每张任务卡必须用 `target_maturity` 绑定证据：DEMO 需要 C3/C4；PILOT 另需 C6 异常、权限与回滚证据或合理 N/A；PRODUCTION 另需 C7 安全、性能/容量、备份恢复、健康/指标/告警、迁移和发布验证，C7 不得用 N/A 代替。业务切片前先通过 `bootstrap-engineering`，基线未通过则 BLOCKED。

## 2. 各阶段最低要求

### READY
- A/B 区完整；验收矩阵覆盖正常、异常、权限和集成场景；不适用项有理由。

### VERIFY
- 现有测试和新增测试真实执行；
- 测试覆盖任务声明的正常、异常和权限路径；
- 至少一个相关集成场景通过；
- 记录命令、环境、依赖、数据种子、迁移和结果。

### REVIEW
- 高风险/关键任务由干净上下文独立 Agent 审查任务卡、diff 和测试证据；
- 审查只查不改，主执行者复核并修复合理项；
- 修复后重新运行相关测试和集成场景；
- 未解决项不得隐藏，不满足条件则返回 BUILD 或 BLOCKED。

### ACCEPT / DONE
- ACCEPT 只表示等待双签，不等于完成；
- DONE 必须产品、工程两项 `APPROVED`；
- 关键生产事项另需人工专业评审，不能仅凭 Agent 双签宣称生产就绪。

## 3. 可复现证据包

至少包含：依赖版本、环境说明、测试数据/随机种子、数据库初始化与迁移、实际命令、预期结果、通过/失败数量、原始输出位置。原始大日志放 `artifacts/` 并设置留存方式，任务卡只写摘要和路径。

## 4. 禁止事项

- 未运行写成通过；
- 以截图、编译成功或单次点击替代业务验证；
- 为通过测试而削弱正确断言；
- 将“独立 Agent 看过”当作无需复现的合格证明；
- 用覆盖率数字替代关键业务场景验证。
