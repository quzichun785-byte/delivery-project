# 母子协作协议

> 主目标是企业级代码交付。母子结构只负责把轻量调研决策与重型工程交付分流，不是目的本身。

## 0. 两类任务，先分流再工作

- 小想法、小决策直接写 INBOX/DECISIONS，不必建卡。
- 正式调研、方案比较和业务决策使用母 `docs/TASKS/` 轻量卡：`DRAFT → RESEARCH → DECIDED → DONE`，只要求一手证据、方案取舍、决策理由和后续动作，不要求测试、集成、回滚或工程双签。
- 只有需要代码实现的决策才由母向子派工程卡，进入完整工程流程。

## 1. 身份与路径

- 母目录只承载产品角色，子目录只承载工程角色；项目根不得放 `CLAUDE.md` 或根级 `.claude/`。
- 双方跨目录读写必须使用绝对路径，不得 `cd` 到对方目录。
- 母子 `docs/PROTOCOL.md` 的 `protocol_version` 必须一致；升级时不自动覆盖运行中项目。

## 2. 一张卡的分区主权

| 区域 | 内容 | 母 | 子 |
|---|---|---|---|
| A 产品定义区 | 背景、目标、业务范围、业务规则、不做项、产品验收 | 可写 | 只读 |
| B 工程设计区 | 技术契约、实现、技术边界、测试设计、工程验收 | 只读 | 可写 |
| C 执行证据区 | diff、测试、集成、审查、回滚证据 | 只读 | 可写 |
| D 变更记录区 | 变更原因、提出方、结论、版本和时间 | 只能追加 | 只能追加 |
| E 双签验收区 | 产品验收、工程验收及各自证据 | 仅产品验收 | 仅工程验收 |

母骨架在 `docs/DISPATCH.md` 只登记任务指针、版本和状态，不复制任务卡正文。子骨架 `docs/TASKS/` 是任务卡唯一存放位置。

## 3. 状态与允许动作

| 状态 | 含义 | 离开条件 |
|---|---|---|
| DRAFT | 母正在起草 | 产品定义完整，母改为 DISPATCHED |
| DISPATCHED | 已派单，子做技术评审 | 子确认可实施并补齐工程验收，进入 READY；产品问题则 BLOCKED_PRODUCT |
| READY | 验收矩阵和工程契约就绪 | 开始实现，进入 BUILD |
| BUILD | 垂直切片实现中 | 实现完成，进入 VERIFY |
| VERIFY | 功能测试与集成验证中 | 证据齐全且通过，进入 REVIEW |
| REVIEW | 独立审查与修复复测中 | 审查问题关闭，进入 ACCEPT |
| ACCEPT | 等母子双签 | 两项均为 APPROVED，进入 DONE |
| DONE | 双签完成 | 新需求另开新卡或新版本，不回写历史证据 |
| BLOCKED | 技术或资料阻塞 | 记录原因与解除条件，恢复到此前状态 |
| BLOCKED_PRODUCT | 产品矛盾、不可实现或范围需变 | 母修订并提升 task_version，重新 DISPATCHED |

## 4. 变更与版本

- 子不得修改 A 区。发现产品问题时，记录问题、影响、可选方案和建议，置为 `BLOCKED_PRODUCT`。
- 母修订 A 区后必须增加 `task_version`，在 D 区追加原因，不得覆盖历史版本说明。
- 子必须记录自己基于哪个 `task_version` 开发；版本不一致不得继续 BUILD。
- 每次状态变化必须在 D 区追加 `日期 | 角色 | status: 源 -> 目标 | task_version=版本`，当前状态与最后转移一致；不得只改 frontmatter。
- 技术补充不缩小产品范围时可由子写入 B 区；若影响产品验收，仍需退回。

## 5. 双签与发布

- 子签工程：实现、测试、独立审查、集成与回滚满足任务卡要求。
- 母签产品：实际结果满足 A 区业务目标、范围和产品验收场景，并填写证据路径、验收人/日期和遗留问题。
- 双签只代表当前任务完成，不自动等于生产发布。最终 ACCEPT -> DONE 必须由母或母子共同确认；子只能签署 E2，不能单独改 DONE。

## 6. 工程基线、成熟度与资产

- 首个业务切片前，子骨架必须执行 `bootstrap-engineering`，按真实开发仓建立依赖、配置、启动、迁移、测试、CI、恢复和可观测性基线；未通过则业务切片 BLOCKED。
- 每张任务卡必须写 `target_maturity`：PILOT 需 C6 异常/权限/回滚证据或合理 N/A，PRODUCTION 另需 C7 生产就绪证据。
- 开发仓、模拟器、部署、旧代码、交付物及证据目录登记到子骨架 `docs/ASSETS.md`；生产运维状态登记到 `docs/OPERATIONS.md`。
