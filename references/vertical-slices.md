# 垂直切片划分标准

## 1. 定义

垂直切片是一个能独立验证的最小业务闭环，可以包含必要的数据、后端、前端、测试、审计和文档。它不是“只改一个函数”，也不是“做完整个模块”。

## 2. 划分规则

- 一个切片只解决一个可验收目标，并有明确不做项。
- 能在一个工作窗口内完成实现和验证；如果必须跳过测试才能结束，说明切片仍太大。
- 每片完成就运行现有系统相关集成流程，不等所有切片完成再统一拼装。
- 先建立可运行的薄骨架，再逐步补齐异常、权限、审计和工程细节。

## 3. 不推荐与推荐

不推荐：全部数据库 → 全部后端 → 全部前端 → 最后统一测试。

推荐示例：
1. 一个角色登录及一个企业级数据隔离；
2. 一个设备档案与模拟数据接入；
3. 单笔读数 → 试算 → 人工复核 → 演示账单；
4. 一条隐患 → 派单 → 整改 → 复核；
5. 一次车辆识别 → 权限判断 → 模拟开闸 → 回执与审计。

## 4. 切片验收前先问

- 正常输入输出是什么？
- 哪些异常必须在片中处理，哪些明确留给后续？
- 是否涉及权限、事务、幂等、并发、审计或回滚？
- 新窗口能否仅凭任务卡和项目文件复现验证？

不能回答时，先缩小或重写切片，不直接开写。
