# 独立审查协议

## 1. 审查独立性

高风险和关键任务必须换一个干净上下文的 Agent。审查者未参与实现，不接受“已经测过”的口头结论，必须读取任务卡、实际 diff 和原始测试证据。

## 2. 风险级别

| 级别 | 示例 | 要求 |
|---|---|---|
| LOW | 明确且简单的展示/文本调整 | 自动测试，轻量审查 |
| MEDIUM | 普通档案、查询、一般接口 | 自动测试与集成验证，按风险抽查 |
| HIGH | 权限、外部接口、数据库迁移、复杂状态 | 独立 Agent 审查 + 异常与集成验证 |
| CRITICAL | 计费、消防、设备控制、生产发布 | 独立审查 + 并发/幂等/回退验证 + 必要时人工专业评审 |

风险默认 HIGH。只有明确理由和批准记录才能降级；关键事项不得由执行 Agent 自行降级。

## 3. 审查内容

- 需求是否被缩小或误读；
- 正常之外的边界、异常、权限和审计；
- 事务、并发、幂等、重试与错误吞噬；
- 测试是否真正断言业务结果，是否实际执行；
- 架构一致性、迁移、部署和回滚；
- 是否存在未声明的范围外修改。

## 4. 复核与复现

审查只查不改。主执行者逐项裁定，合理项修复后重新测试。关键问题优先由独立 Agent 按文档复现，而不是只评论代码外观。审查者无发现也允许，不要求为凑数制造问题。

返回格式：确认错误 E、表述/设计风险 R、轻微观察、已核实无误项、是否满足进入 ACCEPT 的条件。
